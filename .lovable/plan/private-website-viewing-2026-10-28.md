# Private website viewing

## What you will get
- Keep the public holding page on the normal website address.
- Add a private viewing link with a shared-password form; no accounts or registration.
- After the password is accepted, show the completed website, including its pages, animations and fictional product demonstration.
- Add a lock action and an expiring viewing session.
- Keep enquiry submissions disabled during the IP hold.

## Protection
- The password has been saved securely and will never be included in the page or downloadable code.
- Protect website content and demonstration files, not just hide them behind a screen.
- Keep all private pages out of search results and shared caches.
- Anyone receiving both the link and password can forward them; changing the password must invalidate earlier viewing sessions.

## Technical approach
- Use server-verified password checks and encrypted, HTTP-only session cookies.
- Keep archived marketing routes outside the public router. Deliver the private interactive website through session-checked server endpoints, including its JavaScript and media, rather than restoring public client imports.
- Verify the hosting path supports protected delivery before exposing archived content; do not rely on middleware to protect static assets.
- Reuse the preserved website rather than redesigning it.

## Verification and release
- Test incorrect passwords, forged cookies, expired sessions, password changes and direct file requests.
- Verify the complete private viewing flow, navigation and product demonstration on desktop and phone layouts.
- Keep public access locked if protected delivery cannot be verified.
- Publishing remains a separate action; do not publish without Andrew requesting it.
